## 一、统一响应体：为什么每个接口都要长一个样

### 1.1 不用统一响应体会怎样

```json
/register   成功 → "注册成功"                    ← 字符串
/login      成功 → {"id":1,"token":"xxx"}        ← 对象
/problem/1  失败 → {"error":"题目不存在"}         ← 又是一个形状
```

前端每接一个接口都要写一套判断逻辑。一百个接口就是一百套。

用了统一响应体：

```json
{"code":200,"message":"成功","data":null}
{"code":409,"message":"用户名已存在","data":null}
{"code":200,"message":"成功","data":{"id":1,"username":"test01"}}
```

前端写**一个拦截器**就能处理全部接口：`code == 200` 就取 `data`，否则弹 `message`。

### 1.2 一个设计决定：HTTP 状态码永远 200

我们返回 409（用户名冲突）时，**HTTP 状态码仍然是 200**，业务码在 body 里的 `code` 字段。

| 做法 | 优点 | 缺点 |
|---|---|---|
| **HTTP 200 + 业务 code**（本项目） | 前端只判断一处；网关/监控不会因为业务失败报错 | 不符合 REST 严格派 |
| HTTP 状态码跟着业务走 | RESTful 更纯正 | 前端要同时判断 HTTP 码和业务码 |

**两种都能自圆其说，唯一不能接受的是全项目混着用。**

### 1.3 `Result<T>` 的四个工厂方法

```java
Result.success()            // 成功，无数据
Result.success(data)        // 成功，有数据
Result.fail(resultCode)     // 失败，用枚举里的默认文案
Result.fail(resultCode, msg) // 失败，自定义文案
```

**为什么用静态工厂而不是 `new Result(...)`？**

构造方法是 `private` 的，外面造不出对象，只能走这四个出口。于是**不可能造出 `code=200` 却 `message="失败"` 这种自相矛盾的对象**。

## 二、分层的边界画在哪

### 2.1 一条请求穿过的四层

```
Controller  ←→  外部世界（HTTP、JSON、状态码）
Service     ←→  业务（注册到底成没成功）
Mapper      ←→  数据库（SQL）
```

**每一层只跟邻居说话。** 具体表现：

| 反例 | 为什么错 |
|---|---|
| `UserService.register(RegisterRequest req)` | Service 知道了 HTTP 的存在 |
| `UserService.register(...)` 返回 `Result<Void>` | Service 知道了给前端看的格式 |
| `UserController` 里直接 `userMapper.selectCount(...)` | Controller 越级访问数据库，业务逻辑和协议搅在一起 |

所以本项目的签名是：

```java
// Controller：HTTP 的形状
public Result<Void> register(@RequestBody RegisterRequest req)

// Service：业务的形状
boolean register(String username, String rawPassword, String nickname)
```

### 2.2 三种"数据形状"，别混

| 类型 | 位置 | 代表 | 特征 |
|---|---|---|---|
| **Entity** | `entity/` | `User` | 和表结构一一对应，12 个字段 |
| **DTO** | `dto/` | `RegisterRequest` | 前端**发进来**的形状，3 个字段 |
| **VO** | `vo/` | `UserVO`（明天写） | 返回给前端的形状，**不含 password** |

**为什么不能直接返回 Entity？**

- 数据库一加字段，接口响应就自动跟着变 → 耦合
- 加一个 `password2`、加一个 `is_admin`，就自己泄露给前端了

> 这是 ROADMAP 里明确写的「不要直接把 Entity 返回给前端」，也是面试高频。

## 三、今天的 Java 语法点

### 3.1 枚举可以带字段和构造器（和 C++ 最大的不同）

```java
public enum ResultCode {
    SUCCESS(200, "成功"),
    CONFLICT(409, "资源冲突");

    private final int code;
    private final String message;
}
```

| C++ | Java |
|---|---|
| `enum class Color { Red, Green }` | 只是一组**整数常量**的别名 |
| 不能带成员变量 | **枚举常量是对象**，可以带字段、构造器、方法 |

**为什么不用 `int` 常量？** 因为枚举让"传一个乱写的 12345"在编译期就过不去。

### 3.2 泛型 = C++ 模板

```java
Result<Void>       // 成功但没数据
Result<UserVO>     // 数据是一个用户
Result<List<Problem>>  // 数据是题目列表
```

一个类通吃所有返回值。

**两个容易懵的点：**

**① 静态方法要自己再声明一次 `<T>`**

```java
public static <T> Result<T> success() { ... }
//            ↑ 这个 <T> 必须写
```

因为静态方法不属于任何实例，它看不到类上的 `<T>`。

**② `new Result<>(...)` 里的 `<>` 是菱形运算符**

让编译器从左边推断类型，等价于 C++ 的 `auto`。

### 3.3 方法引用 = C++ 的 lambda 简写

```java
User::getUsername        // 等价于 u -> u.getUsername()
```

用在 `LambdaQueryWrapper` 里：

```java
new LambdaQueryWrapper<User>().eq(User::getUsername, username)
```

**好处：字段名写错编译期就报错。** 换成字符串写法 `.eq("user_name", ...)`，拼错了只能运行时炸。

### 3.4 `@RequiredArgsConstructor` + `final` = 构造器注入

```java
@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {
    private final UserMapper userMapper;
    private final BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();
    //      ↑ 有初始值，Lombok 会跳过它，不放进构造方法
}
```

Lombok 生成：

```java
public UserServiceImpl(UserMapper userMapper) {
    this.userMapper = userMapper;
}
```

Spring 看到只有一个构造方法，自动把 `UserMapper` 塞进来。

**比 `@Autowired` 字段注入好在哪：**

- 字段是 `final` 的，不会被中途改掉
- 单测能直接 `new UserServiceImpl(mockMapper)`
- 缺依赖时**启动就报错**，而不是运行到那一行才 NPE

### 3.5 `selectCount` 返回 `Long` 不是 `int`

```java
Long count = userMapper.selectCount(...);
```

因为 SQL 的 `COUNT(*)` 理论上能超过 `int` 上限（21 亿）。写成 `int count = ...` 编译直接报错。

## 四、MyBatis-Plus 今天新碰到的三件事

### 4.1 `LambdaQueryWrapper` 拼的是什么 SQL

```java
userMapper.selectCount(new LambdaQueryWrapper<User>().eq(User::getUsername, username));
```

生成的 SQL：

```sql
SELECT COUNT(*) FROM user WHERE (username = ?)
```

### 4.2 `null` 字段不拼进 SQL（这解释了很多事）

MyBatis-Plus 默认字段策略是 **`NOT_NULL`**：**字段为 `null` 就不出现在 SQL 里**。

```java
User user = new User();
user.setUsername("test01");
user.setPassword(encoded);
user.setNickname("xiaojiu");
// role / status / submit_count / accepted_count / create_time 全是 null
userMapper.insert(user);
```

实际执行的 SQL：

```sql
INSERT INTO user ( username, password, nickname ) VALUES ( ?, ?, ? )
```

**只有 3 列。** 其余列由数据库的 `DEFAULT` 填：

```sql
role           TINYINT NOT NULL DEFAULT 0
submit_count   INT     NOT NULL DEFAULT 0
accepted_count INT     NOT NULL DEFAULT 0
status         TINYINT NOT NULL DEFAULT 1
create_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP
update_time    DATETIME NOT NULL DEFAULT CURRENT_TIMESTAMP ON UPDATE CURRENT_TIMESTAMP
```

> **审计字段的正确做法**：让数据库管 `create_time` / `update_time`，别在每个业务方法里 `setCreateTime(LocalDateTime.now())`。今天一行 Java 都没写，两条时间照样有值。

**这个"不传就有默认值"的机制什么时候会坏？** 当你自己手写 SQL、或者用了显式把所有列都列出来的写法时。那时候 `NOT NULL` 列传 `null` 就会报 `Column 'xxx' cannot be null`。

### 4.3 `@Mapper` 和 `@Service` 的区别

| | `@Mapper` | `@Service` |
|---|---|---|
| 谁注册这个 Bean | Spring + MyBatis 的**扫描器** | Spring 自己的**组件扫描** |
| 注册的是什么 | **动态生成的代理对象**（你没写过实现类） | **你自己写的类的实例** |
| 本质 | 把"接口调用"翻译成"SQL" | 装业务逻辑 |

两者在容器里地位完全平等，都是 Bean。**区别只在"谁生成的"。**

## 五、注册接口的完整链路（代码存档）

### 5.1 `ResultCode.java`

```java
package com.oj.common;

import lombok.Getter;
import lombok.RequiredArgsConstructor;

@Getter
@RequiredArgsConstructor
public enum ResultCode {
    SUCCESS(200, "成功"),
    PARAM_ERROR(400, "参数错误"),
    UNAUTHORIZED(401, "未登录"),
    FORBIDDEN(403, "无权限"),
    NOT_FOUND(404, "资源不存在"),
    CONFLICT(409, "资源冲突"),
    ERROR(500, "系统错误");

    private final int code;
    private final String message;
}
```

### 5.2 `Result.java`

```java
package com.oj.common;

import lombok.Data;

@Data
public class Result<T> {

    private int code;
    private String message;
    private T data;

    private Result(int code, String message, T data) {
        this.code = code;
        this.message = message;
        this.data = data;
    }

    public static <T> Result<T> success() {
        return new Result<>(ResultCode.SUCCESS.getCode(), ResultCode.SUCCESS.getMessage(), null);
    }
    public static <T> Result<T> success(T data) {
        return new Result<>(ResultCode.SUCCESS.getCode(), ResultCode.SUCCESS.getMessage(), data);
    }
    public static <T> Result<T> fail(ResultCode rc) {
        return new Result<>(rc.getCode(), rc.getMessage(), null);
    }
    public static <T> Result<T> fail(ResultCode rc, String message) {
        return new Result<>(rc.getCode(), message, null);
    }
}
```

### 5.3 `UserServiceImpl.java`（今天唯一的硬骨头）

```java
@Service
@RequiredArgsConstructor
public class UserServiceImpl implements UserService {

    private final UserMapper userMapper;
    private final BCryptPasswordEncoder passwordEncoder = new BCryptPasswordEncoder();

    @Override
    public boolean register(String username, String rawPassword, String nickname) {

        // ① 先查重，给用户友好提示
        Long count = userMapper.selectCount(
                new LambdaQueryWrapper<User>().eq(User::getUsername, username));
        if (count > 0) {
            return false;
        }

        // ② 组装实体，密码在这里变成哈希
        User user = new User();
        user.setUsername(username);
        user.setPassword(passwordEncoder.encode(rawPassword));
        user.setNickname(nickname);

        // ③ 数据库层的最后一道防线
        try {
            userMapper.insert(user);
        } catch (DuplicateKeyException e) {
            return false;
        }
        return true;
    }
}
```

### 5.4 `UserController.java`

```java
@RestController
@RequestMapping("/api/user")
@RequiredArgsConstructor
public class UserController {

    private final UserService userService;

    @PostMapping("/register")
    public Result<Void> register(@RequestBody RegisterRequest req) {
        boolean ok = userService.register(
                req.getUsername(), req.getPassword(), req.getNickname());
        return ok ? Result.success() : Result.fail(ResultCode.CONFLICT, "用户名已存在");
    }
}
```

### 5.5 请求进来之后发生了什么（关键：你的代码只占一环）

```
浏览器/curl 发出 HTTP 请求
  ↓
Tomcat（Servlet 容器）收到 socket      ← 第一个碰请求的是它，不是 Spring
  ↓
DispatcherServlet 根据 @RequestMapping 找到方法
  ↓
用 @RequestBody 把 JSON 反序列化成 RegisterRequest
      （Jackson 调用 Lombok 生成的 setter）
  ↓
从容器里拿到 UserService 的实现（构造器注入的那个）
  ↓
调用 register(...)                     ← 你的代码只在这里
  ↓
返回值用 Jackson 序列化成 JSON
  ↓
写回 socket
```

## 六、check-then-act 与两层防护

### 6.1 查重了为什么还要 catch

```
线程A: 查 "test01" → 不存在 ✗
                              ← 就这 1 毫秒
线程B: 查 "test01" → 不存在 ✗
线程A: INSERT → 成功
线程B: INSERT → 违反 UNIQUE 约束 → 抛 DuplicateKeyException
```

这叫 **check-then-act 竞态**（先检查后执行）。

| 防线 | 在哪 | 作用 | 挡什么 |
|---|---|---|---|
| ① `selectCount` | Java | 提示"用户名已存在" | 顺序执行时的重复 |
| ② `UNIQUE uk_username` | 数据库 | 抛 `DuplicateKeyException` | **并发**下的重复 |
| ③ `catch` | Java | 把异常翻译成 409 | 让用户看到人话而不是 500 |

**一句话：代码负责友好，数据库负责正确。**

> 这个道理和昨天笔记里的「唯一约束：两层都要」是同一件事，今天终于落成代码了。

### 6.2 为什么只需要引 `spring-security-crypto`

```xml
<dependency>
    <groupId>org.springframework.security</groupId>
    <artifactId>spring-security-crypto</artifactId>
</dependency>
```

如果引整个 `spring-boot-starter-security`，它会自动配置一套过滤链，**全站接口立刻变成 401**，还带一个默认登录页。

只引 `spring-security-crypto` 就只是拿到 `BCryptPasswordEncoder` 这个类，没有自动配置。

**这就是面试会问的"starter 到底帮你干了什么"的活例子。**

## 七、三种失败：400 / 409 / 500

今天三种全碰过了，这是今天最值钱的收获。

| 状态 | 含义 | 卡在哪 | 该往哪查 |
|---|---|---|---|
| **400** Bad Request | **你的请求有问题** | 还没进你的方法 | 请求体格式、JSON 语法、编码、字段类型 |
| **409** Conflict | **业务规则冲突** | 你的方法里主动返回 | 查重逻辑、`ResultCode.CONFLICT` |
| **500** Internal Server Error | **我的代码/环境有问题** | 方法里抛了异常 | **服务端日志**，不是改代码 |

### 口诀

> **400 怪请求，409 怪业务，500 怪自己。**

### 今天两次真实案例

**案例 1：400 —— 中文被 GBK 编码了**

Git Bash 跑在中文 Windows 控制台（代码页 936），敲的 `小九` 发出去是 GBK 字节，HTTP 头却声明 JSON（按 UTF-8 解析）→ 非法字节序列 → `HttpMessageNotReadableException` → 400。

> 修法：把 JSON 写进文件再 `--data-binary @file`。或者测试时先用英文。

**案例 2：500 —— SSH 隧道断了**

```
netstat -an | grep 3306     → 没有任何一行
```

应用连 `127.0.0.1:3306`，那个端口靠 SSH 隧道转发到服务器。隧道没开 → Hikari 连不上 → 第一次 `selectCount` 就抛异常 → Spring 兜底 500。

> **HikariCP 连接池第一次连失败后会记住失败状态**，隧道修好之后也要重启应用。

**教训：看到 500，第一反应是看服务端日志和网络，不是改代码。**

### 没有全局异常长什么样

```json
{"timestamp":"2026-11-23T14:23:09.567+00:00","status":500,
 "error":"Internal Server Error","path":"/api/user/register"}
```

**连"数据库连不上"都没告诉你。** 这就是明天第一件事要写 `GlobalExceptionHandler` 的动机——不是为了好看，是为了**下次出事能一眼看出是哪一类问题**。

## 八、注解到底是什么（"没有实感"的根源）

> 今晚的真实困惑：代码在做什么大致懂了，但带 `@` 的代码、Spring Boot、MySQL 具体在干什么，没有实感。

### 8.1 为什么没有实感

你熟悉的编程是**你控制流程**：

```cpp
int main() { read(); solve(); print(); }   // 每一步都是我调的
```

Spring 是反的：**框架调你**。整条链上你只写了中间一行，上面和下面全是框架写的。

这叫**控制反转（IoC）**。**你不在控制流的主干上，你在被调用的位置上。**

> C++ 里的同类：`std::sort(v.begin(), v.end(), cmp)` —— 你写 `cmp`，`sort` 在合适的时候调它。你不会问"cmp 为什么被调用"。
> Spring 就是把这个思想放大到整个应用：**写一堆回调，交给容器去调。**

### 8.2 注解的准确语义：登记表，不是代码

```java
@Service
public class UserServiceImpl implements UserService { ... }
```

`@Service` **不产生任何行为**。它唯一的作用是：

> 启动时 Spring 的扫描器走到这个包，看到 `@Service`，就把 `UserServiceImpl` **new 一个实例，放进容器，登记上"UserService 这个类型归它管"**。

| 注解 | 真实语义 |
|---|---|
| `@Service` / `@Component` | 登记进容器 |
| `@RestController` | 登记进容器 + 方法要映射到 HTTP |
| `@RequestMapping("/api/user")` | 这个类下所有方法都挂在这个前缀下 |
| `@PostMapping("/register")` | POST /api/user/register 对应这个方法 |
| `@RequestBody` | 这个参数从请求体反序列化 |
| `@Mapper` | MyBatis 扫描器生成代理类并登记 |
| `@Data` | 编译期生成 getter/setter/toString/equals/hashCode |
| `@TableName("user")` | 这个类对应 user 表 |

**全是元数据。全是给框架看的纸条。**

### 8.3 MySQL 和 Spring Boot 为什么感觉不同

| | MySQL | Spring Boot |
|---|---|---|
| 是什么 | **另一个进程**，跑在服务器上 | **你的程序本身**的骨架 |
| 怎么交互 | TCP + SQL 字符串 | 它调你 |
| 有外部感吗 | 有，能 ps、能 kill、能 `EXPLAIN` 怼它 | 没有，就是你的 jar |

**MySQL 是一个你能怼的对象；Spring Boot 是那个怼你的东西。**

## 九、破坏性实验清单

> **建立实感的唯一有效办法：删掉它，看它怎么死。**
> 每次只删一个，重启，**把报错原文读一遍**，再改回来。

| # | 删/改什么 | 预期现象 | 学到什么 |
|---|---|---|---|
| 1 | 注释掉 `UserServiceImpl` 的 `@Service` | 启动报 `required a bean of type 'UserService' that could not be found` | **Bean 是什么**：容器里的一个对象，没登记就没人能拿到 |
| 2 | `@RestController` 改成 `@Controller` | 返回 404 或"无法解析视图" | `@RestController` = `@Controller` + `@ResponseBody` |
| 3 | 删掉 `@RequestBody` | `username` 变 `null`，插入失败 | 它决定"从请求体取"还是"从 URL 参数取" |
| 4 | `@TableName("user")` 改成 `@TableName("user_xxx")` | `Table 'oj.user_xxx' doesn't exist` | 类→表的映射真实存在，日志里能看到 `INSERT INTO user_xxx` |

**建议节奏**：一天做两个，一周补齐。

## 十、今日踩坑记录

### 10.1 IDEA 报"找不到符号 getCode()"，但 `mvn compile` 通过

**现象**：

```
[ERROR] Result.java:[19,47] 找不到符号
  符号: 方法 getCode()
  位置: 类型为 com.oj.common.ResultCode 的变量 SUCCESS
```

**根因**：`.idea/misc.xml` 里 `project-jdk-name="temurin-25"`。IDEA 用 **JDK 25** 编译，**Lombok 1.18.48 在 JDK 25 下的注解处理器静默失效** → `getCode()` 根本没被生成。

而命令行 Maven 用 **JDK 21** → Lombok 正常 → 编译通过。同一个 pom、同一份代码，两个 JDK，两个结果。

**修法（三处都要）**：

| 位置 | 项 | 值 | 存在哪个文件 |
|---|---|---|---|
| 项目结构 → 项目 | SDK | `temurin-21` | `.idea/misc.xml` |
| 设置 → 构建工具 → Maven → 导入 | 导入程序的 JDK | `temurin-21` | `.idea/workspace.xml` |
| 设置 → 构建工具 → Maven → 运行程序 | JRE | `temurin-21` | `.idea/workspace.xml` |

**两条可复用的经验**：

1. **"IDEA 报错但 `mvn compile` 通过" → 一定是 IDE 配置问题，不是代码问题。** 命令行是权威。
2. **IDEA 的设置只在关闭窗口/切走时才写盘**，改完立刻去看文件可能没变化，别慌。

### 10.2 中文昵称导致 400

Git Bash + 中文 Windows 控制台（代码页 936）→ 发出的是 GBK 字节 → 服务器按 UTF-8 解析失败 → 400。

**修法**：JSON 写进文件再发。

```bash
cat > /tmp/reg.json <<'EOF'
{"username":"test02","password":"123456","nickname":"小九"}
EOF
curl -X POST http://localhost:8080/api/user/register \
  -H "Content-Type: application/json" --data-binary @/tmp/reg.json
```

### 10.3 SSH 隧道断了，表现为 500

应用连 `127.0.0.1:3306`，隧道没开就是空的。**排查第一步永远是 `netstat -an | grep 3306`。**

修好后要**重启应用**（HikariCP 会记住失败状态）。

### 10.4 PowerShell 里跑 bash 命令

| bash | PowerShell 等价 |
|---|---|
| `grep x` | `Select-String x` |
| `&&` | 用 `;` 或分开敲 |
| `curl -X POST -d ...` | **不能直接用**（`curl` 是 `Invoke-WebRequest` 的别名）→ 用 `Invoke-RestMethod` |
| `mysql` | 不在 PATH，全路径 `D:\mysql-8.4.9-winx64\bin\mysql.exe` |

### 10.5 JSON 里字段名打错，接口不报错

把 `nickname` 打成 `nnickname`，接口仍然返回 200，只是 `nickname` 变成 `NULL`。

**因为 Spring Boot 默认关闭了 Jackson 的 `FAIL_ON_UNKNOWN_PROPERTIES`**，不认识的字段直接忽略。

> 想严格：`spring.jackson.deserialization.fail-on-unknown-properties: true`
> **但现在别加**，等 D5 和前端联调时再加，否则前端多传个字段你就 400。
