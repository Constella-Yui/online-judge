# 一、Java 基础语法与语言特性

## 1.1 访问控制与修饰符

| 知识点                  | 核心结论                                                               |
| -------------------- | ------------------------------------------------------------------ |
| 四种访问级别               | `public` > `protected` > 包级私有 > `private`                          |
| 包级私有                 | 不写修饰符 = 同包可见、包外不可见；类/字段/方法/构造器都适用                                  |
| 接口方法默认               | `public abstract`，不是包级私有                                           |
| 接口字段默认               | `public static final`                                              |
| 类里不写修饰符              | 包级私有，**不是** `public`                                               |
| 顶层类可用修饰符             | 只有 `public` 或不写；不能 `protected` / `private`                         |
| 重写权限规则               | 重写方法访问级别 ≥ 被重写方法，**不能收窄**                                          |
| 接口实现必须 `public`      | 接口方法隐式 `public`，实现类写 `double area()` 会报 `weaker access privileges` |
| `private` 不参与重写      | 子类同名方法是新方法，不是重写                                                    |
| `final` / `abstract` | 不是访问修饰符，不影响可见性                                                     |

## 1.2 类与文件

| 知识点 | 核心结论 |
|---|---|
| `public` 类文件名 | 必须和类名一致 |
| 包级私有类文件名 | 不必一致，一个文件可放多个包级私有类 |
| 一个文件最多一个 `public` 顶层类 | 是 |
| 编译产物 | 每个类各自生成 `.class` |

## 1.3 接口 `interface`

| 知识点 | 核心结论 |
|---|---|
| 本质 | 能力契约，规定"能做什么"，不规定"怎么做" |
| 关键字 | 定义 `interface`，实现 `implements` |
| 能否实例化 | 不能，只能指向实现类对象 |
| 方法类型 | 抽象方法、`default`、`static`、`private`（Java 9+） |
| 字段 | 只能 `public static final` 常量，不能有实例状态 |
| 构造器 | 没有 |
| 多实现 | 一个类可实现多个接口 |
| 多继承 | 接口可 `extends` 多个接口 |
| `default` 冲突 | 两个接口同签名 `default`，实现类必须重写并用 `A.super.hello()` 选择 |
| 函数式接口 | 只有一个抽象方法，可用 lambda；如 `Runnable`、`Comparator`、`Function` |

> **补充**：接口的 `static` 方法**只能通过接口名调用**（`Shape.helper()`），不能通过实现类名或实例调用。这个细节常考。

## 1.4 接口 vs 抽象类

| 维度 | 接口 | 抽象类 |
|---|---|---|
| 关键字 | `implements` | `extends` |
| 数量 | 多实现 | 单继承 |
| 状态 | 无实例字段 | 可有实例字段 |
| 构造器 | 无 | 有 |
| 设计意图 | 能做什么 | 是什么 |
| 选型 | 能力契约、跨类型 | 共享状态/代码、类型骨架 |
| 组合 | 接口定契约 + 抽象类给骨架（如 `List` / `AbstractList` / `ArrayList`） |

## 1.5 多态与引用类型

| 知识点 | 核心结论 |
|---|---|
| `Shape s = new Circle(2)` | 编译时类型 `Shape`，只能调 `Shape` 声明的方法 |
| `Circle s = new Circle(2)` | 编译时类型 `Circle`，可调 `Circle` 全部方法 |
| 对象本身 | 两种写法 `new` 出来的对象完全一样，区别只在变量声明类型 |
| 强转 | `((Circle) s).getRadius()`，可能 `ClassCastException` |
| 安全强转 | `if (s instanceof Circle c)`（Java 16+ 模式匹配） |
| 运行时多态 | 同一 `s.area()` 调用，实际执行各自实现 |

> **补充**：`null instanceof Circle` 返回 `false`，**不抛 NPE**。所以 `instanceof` 判断本身不需要先判空。

## 1.6 `default` 方法

| 知识点 | 核心结论 |
|---|---|
| 引入版本 | Java 8（2014） |
| 解决的问题 | 给已有接口加方法而不破坏所有实现类（二进制兼容） |
| 历史案例 | `Collection.stream()`、`Map.merge()`、`List.sort()`、`Comparator.reversed()` |
| 冲突处理 | 多接口同名 `default` 必须显式重写 |
| 与抽象类边界 | 接口可带行为但不能带状态；抽象类可带状态 |
| 代价 | 接口不再纯粹、菱形冲突、设计难度上升 |

# 二、集合与数据结构

## 2.1 Map 家族

| 类型 | 特点 |
|---|---|
| `HashMap` | 无序、允许 null 键值、非线程安全、默认选择 |
| `LinkedHashMap` | 插入顺序 / 访问顺序，可做 LRU |
| `TreeMap` | 按键排序、范围查询、键不允许 null |
| `Hashtable` | 遗留类、方法级 synchronized、不允许 null |
| `ConcurrentHashMap` | 线程安全、不允许 null |
| `ConcurrentSkipListMap` | 并发 + 有序 |
| `WeakHashMap` | 弱引用键，适合缓存 |
| `IdentityHashMap` | 用 `==` 比较键 |
| `EnumMap` | 键是枚举，数组实现，性能最好 |
| `Properties` | 配置文件，实际 `String → String` |

## 2.2 Map 接口继承

```text
Map
├── SortedMap → NavigableMap
└── ConcurrentMap → ConcurrentNavigableMap
```

## 2.3 "类似 Map"的东西

| 类型 | 关系 |
|---|---|
| `Set` | 内部就是一个 `Map`，只有键 |
| `List` / 数组 | `int → 元素` 的映射 |
| `ThreadLocal` | 线程 → 值的映射 |
| `Optional` | 0 或 1 个值 |
| Guava `Multimap` | 一键多值 |
| Guava `BiMap` | 双向映射 |
| Guava `Table` | 二维表 |
| Guava `Cache` | 带过期 / 容量的缓存 |
| Spring `MultiValueMap` | 一键多值 |
| Commons `BidiMap` / `MultiValuedMap` | 双向 / 多值 |

> **修正**：`HashSet` 内部是 `HashMap<E, Object>`，value 是一个**全局共享的哑对象** `PRESENT`（`private static final Object PRESENT = new Object()`），**不是 `Boolean`**。所以 `set.add(e)` 实际是 `map.put(e, PRESENT)`，返回 `null` 表示是新元素。

## 2.4 `Map<String,Integer> freq = new HashMap<>()`

| 知识点 | 核心结论 |
|---|---|
| 含义 | 声明为 `Map` 接口，创建 `HashMap` 对象 |
| 左边 `Map` | 只暴露接口方法，便于替换实现 |
| 右边 `HashMap` | 实际对象 |
| 为什么左边不写 `HashMap` | 面向接口编程，换实现只改右边，方法参数/返回值更通用，便于测试 Mock |
| 何时可写具体类型 | 局部短生命周期、确需实现类独有方法、框架特殊要求 |

## 2.5 计数相关 API

| API | 作用 |
|---|---|
| `freq.merge(k, 1, Integer::sum)` | 不存在放 1，存在则旧值 + 1，**最简洁计数写法** |
| `freq.getOrDefault(k, 0) + 1` | 等价但两步操作 |
| `freq.computeIfAbsent(k, x -> 0)` | 不存在时初始化 |
| `freq.putIfAbsent(k, v)` | 不存在才放 |
| `freq.entrySet()` | 所有键值对的 Set 视图 |
| `freq.keySet()` / `values()` | 键集合 / 值集合 |
| `removeIf` | 边遍历边删除的推荐写法 |

## 2.6 `entrySet` 与 `Map.Entry`

| 知识点             | 核心结论                                            |
| --------------- | ----------------------------------------------- |
| `entrySet()` 返回 | `Set<Map.Entry<K,V>>`                           |
| `Entry` 能力      | `getKey()`、`getValue()`、`setValue()`（会同步改原 Map） |
| 转 List          | `new ArrayList<>(freq.entrySet())` 浅拷贝引用        |
| 排序影响原 Map       | 只排序 List 不影响 Map；`setValue` 会影响                 |

# 三、排序与比较

## 3.1 默认顺序

| 工具 | 默认顺序 |
|---|---|
| `Arrays.sort(int[])` | 升序 |
| `Arrays.sort(T[])` | 升序 |
| `Collections.sort(list)` | 升序 |
| `List.sort(null)` | 升序 |
| `stream.sorted()` | 升序 |
| `TreeSet` | 升序 |
| `TreeMap` | 键升序 |
| `PriorityQueue` | **小顶堆**（poll 出最小值） |
| `Comparator.naturalOrder()` | 升序 |
| `Comparator.comparing(...)` | 升序 |

**统一结论：默认全是升序，唯一特殊是 `PriorityQueue` 默认小顶堆。**

## 3.2 降序写法

```java
Comparator.reverseOrder()
comparing(...).reversed()
Collections.reverseOrder()
new TreeSet<>(Comparator.reverseOrder())
new PriorityQueue<>(Comparator.reverseOrder())
```

## 3.3 `Comparator.compare` 返回值

| 返回值 | 含义 |
|---|---|
| 负数 | `a` 在前 |
| 0 | 相等 |
| 正数 | `a` 在后 |

```java
(a, b) -> a - b            // 升序（有溢出风险）
(a, b) -> b - a            // 降序（有溢出风险）
Integer.compare(a, b)      // 安全
```

> **补充**：`Comparator.comparingInt(...)` 优于 `Comparator.comparing(...)`——前者直接返回 `int`，**不装箱**。LeetCode 上对大数据量排序时差别明显。

## 3.4 `reversed()` 的位置

```java
comparing(A).reversed().thenComparing(B)   // A 降序，A 同则 B 升序
comparing(A).thenComparing(B).reversed()   // 整体反转：A 降序，A 同则 B 降序
```

## 3.5 常见坑

| 坑 | 说明 |
|---|---|
| 基本类型数组不能自定义比较器 | `Arrays.sort(int[], Comparator)` 不存在 |
| `PriorityQueue` 遍历无序 | 只有 `poll()` 有序 |
| `Collections.reverse` 不是排序 | 只是反转 |
| `String.compareTo` 非人类字典序 | `"Z" < "a"`，中文按码点 |
| `TreeSet` / `TreeMap` 用比较器判重 | 返回 0 视为重复 |
| `Arrays.sort` 基本类型不稳定 | 双轴快排；对象数组 / List 稳定（TimSort） |
| `null` 元素 | 用 `Comparator.nullsFirst` / `nullsLast` |

## 3.6 词频排序模板

```java
List<Map.Entry<String,Integer>> list = new ArrayList<>(freq.entrySet());
list.sort(
    Comparator.comparing(Map.Entry<String,Integer>::getValue)
              .reversed()
              .thenComparing(Map.Entry::getKey)
);
```

> 已实测：这段可直接编译运行。（练习② 手写的 lambda 版和这个等价）

# 四、数值与溢出

## 4.1 `int` 范围与溢出

| 知识点 | 核心结论 |
|---|---|
| `int` 范围 | `-2^31` ~ `2^31-1` |
| 溢出行为 | **静默回绕**，不抛异常 |
| 两个非负数相减 | **不会溢出**（结果在 `[-MAX, MAX]`） |
| 正减负、负减正 | 可能溢出 |
| `b - a` 溢出条件 | `b > 0 && a < 0` 且差值超 MAX；或 `b < 0 && a > 0` 且差值低于 MIN |
| 词频场景 | 值非负，`b - a` 实际不会溢出 |
| 通用推荐 | `Integer.compare(a, b)`，只返回 -1/0/1，永不溢出 |
| 替代 | `Long.compare((long) a, (long) b)` |
| 拆箱 NPE | `Integer` 为 null 时参与运算抛 NPE |

## 4.2 `Integer.parseInt`

| 输入 | 结果 |
|---|---|
| `"123"` | 123 |
| `"-45"` | -45 |
| `"+67"` | 67 |
| `""` | `NumberFormatException` |
| `" 123 "` | `NumberFormatException`（不自动 trim） |
| `"1.5"` | `NumberFormatException` |
| `"2147483648"` | `NumberFormatException`（超范围） |
| `null` | `NumberFormatException` |

> **修正**：`parseInt(null)` 的**异常信息**随 JDK 版本变化。JDK 21 实测是 `NumberFormatException: Cannot parse null string`，老版本才是 `: null`。**记异常类型就好，别记具体文案。**

# 五、IO 与输入输出

## 5.1 `BufferedReader` 三层包装

```java
BufferedReader br = new BufferedReader(new InputStreamReader(System.in));
```

| 层 | 类型 | 职责 |
|---|---|---|
| `System.in` | `InputStream` | 字节流，标准输入 |
| `InputStreamReader` | `Reader` | 字节 → 字符，按编码解码 |
| `BufferedReader` | `Reader` | 加缓冲，提供 `readLine()` |

- 装饰器模式，每层加一种能力
- `BufferedReader` 默认缓冲 **8192 字符**
- 比 `Scanner` 快，大输入首选
- 编码建议显式 `StandardCharsets.UTF_8`

## 5.2 `readLine()` 细节

| 情况   | 返回            |
| ---- | ------------- |
| 正常一行 | 不含行尾换行的字符串    |
| 空行   | `""`（不是 null） |
| EOF  | `null`        |

**`null` 和 `""` 完全不同，`null.trim()` 会 NPE。**

> **补充**：行尾的 `\r`（Windows 换行）会被**吃掉**，不会留在返回的字符串里。所以 Windows 上读文件不用手动去 `\r`。

## 5.3 `trim()` vs `strip()`

| 方法 | 范围 |
|---|---|
| `trim()` | 去掉首尾码点 `<= U+0020` 的 ASCII 空白 |
| `strip()`（Java 11+） | 按 `Character.isWhitespace`，含 Unicode 空白 |

## 5.4 常见写法

```java
// 读一行整数
int n = Integer.parseInt(br.readLine().trim());

// 读一行多个整数
String[] parts = br.readLine().trim().split("\\s+");

// 读所有行
String line;
while ((line = br.readLine()) != null) { ... }

// StringTokenizer（更快）
StringTokenizer st = new StringTokenizer(br.readLine());
```

## 5.5 异常

- `readLine()` 声明 `throws IOException`
- 竞赛常用 `public static void main(String[] args) throws IOException`
- 工程用 `try-with-resources`，但**不要随便关 `System.in`**

# 六、字符串与正则

## 6.1 `StringBuilder`

| 方法                                             | 作用                                     |
| ---------------------------------------------- | -------------------------------------- |
| `append(...)`                                  | 追加，支持链式                                |
| `insert(index, ...)`                           | 插入                                     |
| `delete(start, end)`                           | 删除区间                                   |
| `deleteCharAt(index)`                          | 删除字符                                   |
| `replace(start, end, str)`                     | 替换区间                                   |
| `reverse()`                                    | 反转                                     |
| `setCharAt(i, c)`                              | 改字符                                    |
| `charAt(i)` / `length()`                       | 取字符 / 长度                               |
| `substring(s, e)`                              | 返回 `String`                            |
| `indexOf` / `lastIndexOf`                      | 查找                                     |
| `setLength(n)`                                 | 截断 / 补 `\0`                            |
| `capacity()` / `ensureCapacity` / `trimToSize` | 容量                                     |
| `toString()`                                   | 转 String                               |
| 清空                                             | `setLength(0)` 或 `delete(0, length())` |

- 非线程安全；多线程用 `StringBuffer`
- `append(int)` 自动转字符串，不用手动拆位

## 6.2 `split` 与正则

| 正则 | 含义 | 用途 |
|---|---|---|
| `\s` | 空白字符 | **分隔符** |
| `\w` | `[a-zA-Z0-9_]` | **内容**，几乎不用于 split |
| `\S` | 非空白 | |
| `\W` | 非单词字符 | 按非字母数字切分 |
| `\s+` | 一个或多个空白 | 最常用切分 |
| `\p{L}+` | Unicode 字母（含中文） | 中文场景 |

**核心区别：`\s` 是分隔符，`\w` 是内容。`split("\\w")` 会按每个字母切，几乎总是错的。**

## 6.3 `split` 常见坑

| 坑 | 说明 |
|---|---|
| Java 字符串双反斜杠 | `"\\s+"`，不是 `"\s+"` |
| `split` 参数是正则 | `"."` 要写 `"\\."` |
| `\w` 不含中文 | 用 `\p{L}` |
| 尾部空串默认丢弃 | `split(",", -1)` 保留 |
| `\s` 不匹配全角空格 | 用 `[\s　]+` |
| 每次 split 编译正则 | 大量切分预编译 `Pattern` |

# 七、循环与代码风格

## 7.1 循环写法选型

| 场景 | 推荐 |
|---|---|
| 数组 / 集合只读遍历 | 增强 for |
| 需要索引 | 普通 for / `IntStream.range` |
| 遍历中删除 | `removeIf` / `Iterator.remove` |
| 打印、简单消费 | `forEach` |
| 过滤 / 映射 / 分组 / 聚合 | Stream |
| 嵌套集合展开 | `flatMap` |
| 多层循环提前退出 | 标签 `break outer` |
| 读流 / 条件循环 | `while` |
| Map 遍历 | `entrySet()` 或 `forEach` |
| 大数据并行 | `parallelStream`（谨慎） |

## 7.2 实践建议

- 简单遍历用增强 for，复杂转换用 Stream
- 不要在 `forEach` 里 `break` / `continue` 或改外部变量
- 删除优先 `removeIf`
- Stream 链不超过 5～6 步
- 性能热点用传统 `for`

# 八、面向对象设计与原则

## 8.1 依赖注入与 IoC

| 概念 | 核心结论 |
|---|---|
| 依赖注入（DI） | 依赖从外部传入，不在类内 `new` |
| 控制反转（IoC） | 控制权从类内部转移到外部容器 / 组装处 |
| 依赖倒置（DIP） | 高层和低层都依赖抽象 |
| 好的 IoC | 注入**抽象**，实现可替换、可测试、解耦 |
| 坏的 IoC | 注入**具体类**，形式是 DI，实质失去解耦价值 |
| `private final ShapeService` | ✅ 依赖抽象 |
| `private final ShapeServiceImpl` | ❌ 依赖具体，不能换实现、难 Mock、违反 DIP |
| 可写具体类型的场景 | 局部短生命周期、确需独有方法、框架特殊要求 |

**关键判断：字段、构造器参数、方法参数、方法返回值，默认写接口。**

## 8.2 面向接口编程

```java
Map<String,Integer> freq = new HashMap<>();
List<Shape> shapes = new ArrayList<>();
ShapeService service = new ShapeServiceImpl();
```

- 左边接口，右边实现
- 换实现只改右边
- 方法参数用接口，调用方可传任意实现
- 便于测试 Mock

## 8.3 隐藏实现类

```java
public interface Shape { double area(); }

class Circle implements Shape { ... }        // 包级私有实现

public class ShapeFactory {
    public static Shape circle(double r) {
        return new Circle(r);                 // 外部只拿到 Shape
    }
}
```

包级私有实现类 + public 工厂 / 接口，是常见解耦手法。

## 8.4 `instanceof` 与强转

```java
if (s instanceof Circle c) {   // Java 16+ 模式匹配
    c.getRadius();
}
```

## 9.6 Maven 依赖下载失败（今天踩的坑，值得记）

**报错**：
```
Could not transfer artifact org.sonatype.plexus:plexus-build-api:jar:0.0.7
from/to aliyun-public (...):
...\plexus-build-api-0.0.7.jar.13798698822895778495.tmp -> ...\plexus-build-api-0.0.7.jar
```

**关键发现**：jar 其实**已经在本机**，而且 SHA-1 和官方一致——坏的是最后一步"改名"。

**两层原因**：

1. **来源对不上**：`~/.m2/repository/.../_remote.repositories` 是 Maven 记录"这个包从哪个仓库下的"的台账。该 jar 的记录里只有 `central` 和一个旧仓库 ID，**没有当前的 `aliyun-public`** → Maven 认为本地副本不可信，每次都要重新下载验证。
2. **改名撞车**：下载完要 `.tmp` → `.jar` 改名，此时文件被另一个进程占着（IDEA 后台同步 / 杀毒扫描），改名失败，留下 `.tmp` 残骸。

**修复**（都在 `~/.m2` 缓存里，无风险）：

```bash
cd ~/.m2/repository/org/sonatype/plexus/plexus-build-api/0.0.7/
rm -f *.tmp *.lastUpdated
# 在 _remote.repositories 里补一行，把 jar 登记到当前镜像名下
echo 'plexus-build-api-0.0.7.jar>aliyun-public=' >> _remote.repositories
```

**预防**：

- ❌ **IDEA 开着时在命令行跑 `mvn`** —— 两个 Maven 进程抢同一个 `~/.m2`
- ✅ 二选一：全程 IDEA 绿色三角，或全程命令行
- ✅ 应急绕过网络：`mvn -o spring-boot:run`（本地依赖齐全时）

**学到的东西**：`~/.m2` 是**缓存目录**，有"来源台账"（`_remote.repositories`）、"失败标记"（`.lastUpdated`）、"下载残骸"（`.tmp`）。这些在配 CI、清理构建环境时都用得上。

# 十五、自检题与订正

> 练习③（接口与多态）结课自检。5 题全部答完，记录原答案 + 批改 + 补充。

## Q1 为什么 `Circle.area()` 必须写 `public`？

**我的回答**：Shape 接口内 `area` 方法声明为 public，实现 Shape 的类也必须对外公开提供 `area`，即重写方法不能比被重写方法更严格。

**批改**：✅ 正确。

**补充**：真正的关键在于——**你就算不写 `public`，它也是 public**。

```java
interface Shape {
    double area();          // 一个字都没写 public
}
```

编译后等价于 `public abstract double area();`。

所以坑不是"忘了写 public"，而是"**不知道它已经是 public 了**"。在 `Circle` 里写 `double area()` 报错时，你看着接口里也没写 public，会觉得"凭什么它可以我不行"。

> **接口里所有方法天然 `public`，你没得选。**

---

## Q2 `Shape s = new Circle(2)` 和 `Circle s = new Circle(2)` 有什么区别？

**我的回答**：两者都新建 `Circle` 对象，但 `Shape s` 只能调用 `Shape` 接口的方法，无法调用 `Circle` 中的独有方法。

**批改**：✅ 正确。

**补充**：用一句话概括——**编译时看声明类型，运行时看实际对象。**

- 编译期：`Shape s` 只认 `Shape` 声明过的方法，`s.getRadius()` 直接编译失败
- 运行期：`s.area()` 实际跑的是 `Circle` 的版本

两者不矛盾，一个是编译期类型检查，一个是运行期动态分派。这就是多态的完整图景。

---

## Q3 什么时候用接口，什么时候用抽象类？

**我的回答**：只需要确定能力契约就用接口，还需要共享状态就用抽象类。`default` 可以在不破坏现有类的情况下为接口加入新方法。

**批改**：✅ 正确，抓住了核心（契约 vs 状态）。

**补充**：面试再补一句**组合用法**——`List`（接口）/ `AbstractList`（骨架）/ `ArrayList`（实现）。

接口定契约，抽象类提供公共骨架代码，具体类只写差异部分。这是 JDK 的标准分层，也是"接口 + 抽象类"一起用而不是二选一的典型例子。

## Q4 ⭐ 字段写成 `ShapeServiceImpl` 而不是 `ShapeService`，还能算 IoC 吗？

这题是**唯一一道答错也不会报错**的题——代码照样跑，只是把未来的路堵死了。

### 精确的措辞：DI 保留，DIP 丧失

| 概念 | 状态 |
|---|---|
| **依赖注入（DI）** | ✅ 还在 —— 依赖确实从构造器传入，类内部没有 `new` |
| **依赖倒置（DIP）** | ❌ 没了 —— 高层（Controller）依赖了低层的**具体实现**，而非抽象 |

> 面试版回答：**形式上算 DI，但 IoC 的价值已经没有了。**

### 场景 A：换实现

明天产品说"面积要缓存"，你写了 `CachingShapeService implements ShapeService`。

- **字段是接口**：`main` 里改一行 `new CachingShapeService()`，Controller **一字不动** ✅
- **字段是具体类**：得去改 `ShapeController` 的字段声明 + 构造器参数 ❌

Controller 不该因为"算法实现变了"而改动。这就是耦合。

### 场景 B：加横切逻辑 ⭐ 杀手锏

想给所有 Service 方法加日志（或事务、计时），**但不改 `ShapeServiceImpl` 一个字**。做法是套一层代理：

```java
class LoggingShapeService implements ShapeService {   // 注意：实现的是接口
    private final ShapeService target;

    LoggingShapeService(ShapeService target) { this.target = target; }

    @Override
    public double totalArea(List<Shape> shapes) {
        System.out.println("[日志] 调用 totalArea");
        return target.totalArea(shapes);
    }
    // largest 同理
}
```

装配：

```java
ShapeService real  = new ShapeServiceImpl();
ShapeService proxy = new LoggingShapeService(real);
ShapeController c  = new ShapeController(proxy);
```

- **字段是 `ShapeService`** → ✅ 编译通过，日志生效，`ShapeServiceImpl` 一行没改
- **字段是 `ShapeServiceImpl`** → ❌

```
error: incompatible types:
       LoggingShapeService cannot be converted to ShapeServiceImpl
```

**为什么传不进去？**

> `LoggingShapeService` **实现了 `ShapeService`，但它不是 `ShapeServiceImpl` 的子类。**

两者是平行的类，只是碰巧实现了同一个接口。类型对不上。

**这就是 Spring AOP 的全部原理。** `@Transactional`、`@Async`、`@Cacheable` 全都是在你不知道的情况下，往你的 Bean 外面套一层代理。

而 **Spring 的 JDK 动态代理只能代理接口**。字段写死成实现类，这条路就断了。

> 面试加分：Spring 也支持 CGLIB 代理（用继承代替实现），但有代价——**`final` 类和 `final` 方法代理不了**。所以"面向接口编程"在 Spring 生态里不是洁癖，是有技术约束的。

### 场景 C：测试 Mock

```java
// 测 ShapeController，不想真的算面积
ShapeService fake = new ShapeService() {          // 匿名类，直接实现接口
    public double totalArea(List<Shape> s) { return 42.0; }
    public Shape largest(List<Shape> s)     { return null; }
};
```

Mockito 之类生成的也是**接口的假实现**，不是实现类的子类。字段写接口直接注入；写具体类就得走 CGLIB，还有一堆限制。

### 类比

| | 接口类型 | 具体类类型 |
|---|---|---|
| 像什么 | 墙上的**标准插座** | 把台灯**焊死在墙上** |
| 今天 | 插台灯，亮 ✅ | 亮 ✅ |
| 明天想换充电器 | 拔了换一个，插座不用动 | 得砸墙 |

**两种都能亮灯。区别在"明天下一步"能不能走。**

### 但要避免教条

**判断标准只有一条：这个类型有没有可能被"另一种实现"替换？**

| 情况 | 写什么 |
|---|---|
| 业务服务、数据访问（可能换实现 / 加事务代理 / 需要 Mock） | **接口** |
| 局部变量、方法内的临时对象 | 具体类无所谓 |
| 确定永不可变的基础设施（如 `String`） | 具体类 |
| 只在一个地方用、不需要横切能力 | 具体类也合理 |

> 但新手期先守纪律：**默认写接口**，等有判断力了再破例。

## Q5 `default` 方法解决什么问题？

**我的回答**：`default` 是为了解决旧时 Java 已发布的接口不能随便加新方法，否则所有实现类都编译失败。它实现了在不破坏现有实现的情况下给接口加新方法。

**批改**：✅ 正确。

**补充**：具体历史案例——Java 8 要加 `Collection.stream()`。

- **没有 `default`**：全世界所有实现了 `Collection` 的第三方库（Guava、Hibernate、无数公司内部框架）**升级 JDK 就编译失败**
- **有 `default`**：老代码原封不动，新方法白送

所以它不是"方便"，是 **Java 生态活下来的必要条件**。

从 C++ 角度看：给纯虚基类加纯虚函数会炸掉所有子类，C++ 做不到无破坏演进；加非纯虚函数又强制所有子类继承一份实现。Java 的 `default` 是第三条路。
